## 1. 方向宣言

**一言: 「バトン帯」。前回の人→今日の人と次の一言を、藍の帯1枚で手渡す。**

- 誰が: 携帯売り場のスタッフ。とくに週末のイベントスタッフと、臨機応変が苦手な人
- 場面: お客様が目の前にいる。スマホを片手に持ち、目を落とせるのは**1回2〜3秒**
- 1画面で何秒で何が分かるか:
  - お客様カード: **3秒**で「先に確認すること(あれば)/次の一言/最初に話す項目」
  - 記録: **30秒以内**(目標の表示は残す)、文字入力0回で保存まで行ける
  - 今日: **1秒で1人**。名前の横で「必ずがあるか」が見える
- 同じ種類のアプリに無いもの(1語): **バトン帯**。CRMの顧客詳細は「属性→履歴」の順に並ぶ。このアプリは「誰から誰へ→次の一言」を最上段に置く。見本 `A_card.png` の藍の帯がそれ
- レジスター: 主=精密(道具として迷わせない)、副=劇場の一点(バトン帯の藍の面)
- サーフェス: web(スマホ縦、390px基準、320pxまで崩さない)

### 書体
- 和文・欧文とも **BIZ UDPGothic**(400 / 700)。`next/font/google` の `BIZ_UDPGothic` で読み込む
  - 理由: モリサワのUD書体。濁点・半濁点・数字の取り違えが起きにくい。売り場の明るい照明と流し読みに向く。既定のヒラギノ+system-uiから意図的に外す
- 数字(日付・下4桁・秒)は `font-variant-numeric: tabular-nums`
- 使うウェイトは 400 と 700 の2つだけ

### 文字の階層(px、行間)
| 役割 | サイズ | 太さ | 行間 |
|---|---|---|---|
| お客様名 | 26 | 700 | 1.2 |
| 次の一言(主役) | 22 | 700 | 1.45 |
| 先に確認・項目名 | 17 | 700 | 1.4 |
| 本文・ボタン | 16 | 400/700 | 1.5 |
| 補足(日付・理由) | 13 | 400 | 1.4 |
| 区切り見出し(話す順 など) | 13 | 700、字間0.08em | 1.3 |
| 最小(見本データ注記・タグ) | 12 | 700 | 1.3 |

13px未満は使わない(タグと注記の12pxだけ例外)。

### 余白(8の倍数、4は細部だけ)
- 画面の左右: 16
- 区画どうし: 12(区画は白い面を全幅で敷き、カードを浮かせない)
- 区画の中の上下: 12〜16
- 一覧の1行の高さ: 52(タップできる行は56)
- タップ領域: 44×44以上

### 角丸・面・影
- 角丸は3種類だけ: 面の中のかたまり 12 / ボタン 10 / 小さなタグ 4。24以上は使わない。丸ピル(999)は使わない
- 区画は**全幅の白い面+上下1pxの線**。角丸の白カードを並べない
- 影は使わない。浮かせたいのは下のタブだけで、それも線1本で区切る

### 色の役割(実HEXは色彩係が決める。モックの値は仮)
| 役割 | 使う場所 | 使わない場所 | モックの仮色 |
|---|---|---|---|
| 地 | 画面の背景 | — | #F3F5F8 |
| 面 | 区画の白 | — | #FFFFFF |
| 文字 / 補足文字 | 本文 / 日付・理由 | 純黒は使わない | #17212B / #5B6878 |
| 藍(構造) | バトン帯の面、ヘッダー、主ボタン、選んだ状態 | 状態の印 | #16324F |
| 朱(止まれ・必ず) | 「先に確認」の面、状態「変更あり・必ず案内」の印 | 保存ボタン、イベント印、装飾 | #D9480F |
| 黄(あいまい) | 状態「前回あいまい・もう一度詳しく」の印と淡い地 | それ以外 | 印 #F2B705 / 地 #FFF6D6 / 文字 #5C4400 |
| まだ | 状態「まだ」= 白抜きの丸+灰の線 | 色で塗らない | 線 #5B6878 |
| 説明済み | 状態「説明済み・まず理解度を伺う」= 淡い藍の丸+チェック | 強い色 | 地 #E6EDF5 / 印 #3E6A8F |
| イベント印 | スタッフ名の横の小さな印 | 朱は使わない(必ずと混ざる) | 線だけのタグ(藍地なら白線、白地なら藍線) |

- 今は「保存ボタン」と「イベント印」が朱(橙)で、「必ず」と同じ色になっている。**朱は止まれ・必ずだけ**に絞る(Codex助言を採用)
- 色だけで状態を伝えない。4状態は必ず**形+記号+言葉**の3つで出す(下の§2-1)
- 色彩係への発注: 上の表の役割ごとに、白地で文字4.5:1・印3:1を満たすHEX。2型色覚のシミュレーションで朱と黄と藍が区別できること

### 動き
- 基準 160ms ease-out。記録画面で段を畳む・開くのは高さのアニメーション 200ms
- 祝う演出は無し。保存したら上に「保存しました・取り消す(5秒)」の帯を出すだけ(取り消しは次の段で。§2-2)
- `prefers-reduced-motion` では動きを切る

## 2. 画面ごとの仕様

### 2-1. お客様カード(最優先)— 見本 `A_card.png`

上から次の順。**390×844 の最初の画面に、5まで(話す順の3行目まで)入る**こと。

1. **見本データの注記**(画面最上部、全幅、12px、濃い藍地に淡い文字)「見本データです(実在のお客様ではありません)」。破線のタグはやめる
2. **名前の行**: お客様名 26px / 下4桁・何回目 14px 補足色
3. **バトン帯**(藍の全幅の面、左右16・上下16〜20)
   - 1行目: `前回の担当(日付・常勤/イベント)` ──▶ `今日の担当(今日)`。名前17px太字、日付13px。矢印は線1本+三角
   - 2行目「何まで」: `用件 ・ 案内した項目まで ・ 温度感`。案内した項目だけ太字。最大2行
   - 3行目「先に確認」(**前々回以前の未完了の約束があるときだけ**): 朱の面、角丸12。左に白地の「先に確認」タグ、本文17px太字「小林さんに『入荷・在庫』『家族と相談』は済んだ?」、補足13px「9/24の約束が未完了のまま」。件数が多いときは担当者ごとに1行
   - 4行目「次の一言」: 白い面、角丸12、左に朱8pxの線。見出し12px朱「次の一言」、本文22px太字。補足13px(なぜこの一言か)
     - 中身は `buildTalkHints` の extra の1番目をそのまま使う。声かけの例がある場合(見積もり未完了)は、**『』の中の声かけを主役の22pxに出し、残り(「見積もりを作りながら詳細を案内する」)を補足13pxに出す**。原文「詳細を見積もりを作りながら、ご案内させていただきますね」は一字も変えない
4. **話す順**(白い全幅の面。見出し13px「話す順」右に「前回 9/28」)
   - 1行52px。左に印28px、項目名17px太字、右に状態ラベル13px
   - 並びは handoff の並び(変更あり → あいまい → まだ)。**説明済みは1行に畳む**:「✓ 説明済み 2件 / 理解度を伺う ▾」。押すと項目名が開く
   - 4状態の見せ方(形・記号・言葉):
     | 状態 | 印 | 右のラベル |
     |---|---|---|
     | 変更あり | 朱の丸に「!」 | 「! 変更あり・必ず案内」朱字 |
     | 前回あいまい | 黄のひし形に「?」 | 「? 前回あいまい」黄の淡い地 |
     | まだ | 白抜きの丸(灰の線2.5px) | 「○ まだ」補足色 |
     | 説明済み | 淡い藍の丸に「✓」 | 「理解度を伺う」藍の補足色、行全体も補足色 |
   - 「変更あり」は**ここにだけ出す**。今の「必ず」区画と「話す順のヒント」での繰り返しはやめる
5. **終わっていない約束**(白い面): 1行56px。約束名16px太字、補足13px「9/24 小林 葵・先に小林さんに確認」、右に「済み」ボタン(枠2px藍、角丸10、44px以上)
6. **これまでの記録**: 畳んだ1行「これまでの記録 2件 開く ▾」。開いた中身は今の履歴の見た目のまま(見本データの表示も残す)
7. 主ボタン「このお客様の記録を残す」藍、角丸12、高さ56

**消すもの**: 「次の人へ」の8行の文章(`buildHandoffSummary().text`)は画面に出さない。読み上げ用に `sr-only` で残すのは可。「必ず(全部)」区画と「話す順のヒント」区画は、上の3〜4に吸収する。ロジックの関数は消さない。

### 2-2. 記録画面(30秒)— 見本 `A_record.png`

- 見出し行: 「記録する」20px 左、右に `3/5 ・ 目標30秒 ・ 12秒` 13〜16px。**秒数を大きくしない、30秒を超えても赤くしない**(急かさない)
- 進み方: **済んだ段は1行に畳む**(高さ48、左に藍の✓、選んだ値を16px太字、右に「変える」)。**今の段だけ開く**(上に朱3pxの線、段名20px)。まだの段は灰の1行(44px、点線区切り)
- 段は5つにまとめる: ①お客様 ②用件 ③案内したこと ④温度感 ⑤次にやること・次回来店予定(任意)。メモは⑤の下に「メモを足す」リンク1つ(押すまで入力欄を出さない)
- 自然に次へ進む:
  - ①お客様: 選んだら自動で②へ
  - ②用件(複数可): チップを押したあと「次へ」。用件は2列のボタン、高さ48
  - ③案内したこと: 項目1行56px、右に2択のセグメント「説明済み / あいまい」(各56px幅以上、44px高)。「あいまい」を押すと説明済みも記録される(今の仕様と同じ)。見出しの下に13px「押さない項目は前回のまま」。「次へ」
  - ④温度感: 4つを2×2のボタン。**押したら自動で⑤へ**
  - ⑤任意: 「なし」で飛ばせる。来店予定は日付のチップ(今日+1/+3/+7/日付を選ぶ)
- 保存ボタン(下に固定、藍、高さ56): **無効にしない**。足りないときに押すと、足りない段を開いてその段へ動く。上に13px「あと:温度感」
- 縦の長さ: どの段を開いていても、**1画面(390×844)+半画面以内**
- 文字入力0回で保存まで行ける(メモと「その他」以外)

### 2-3. 今日の一覧 — 見本 `A_today_v1.png`

- 1人=全幅の白い行(カードを浮かせない)。名前19px太字、右に下4桁・前回担当13px
- 2行目: 「次の一言」12px補足+一言15px(1行で切る。`buildTalkHints` の1番目)
- **必ずがある人だけ**、名前の横に朱のタグ「必ず 1」(数=先に確認+変更ありの件数)
- 見本の色丸と数字の並び(凡例なし)は**やめる**(Codex指摘)。代わりに3行目を言葉で「変更あり1 ・ あいまい1 ・ まだ2」13px。0の状態は書かない
- 前回担当がイベントスタッフなら、名前の後ろに線だけのイベント印
- 「このあと今週」は1行48pxの簡易行(名前・日付・用件)
- 「記録にかかった時間(目標30秒以内)」の区画は残す

## 3. AIっぽさを消す: 禁止とやること

**禁止**
1. 情報を全部文で出す(要約文・ヒント文・状態文が同じことを3回言う)
2. 角丸16〜24の白いカードを縦に並べる/カードの中にカード
3. 丸ピルのチップを状態にも用件にも使う(全部が同じ形になる)
4. 1色(橙)に「保存・イベント・必ず」の3つの意味を持たせる
5. 番号つきの丸(①②③)を飾りで使う
6. 凡例のない色丸+数字
7. 既定の書体(ヒラギノ+system-ui)をそのまま出す
8. 「AIが要約しました」のような説明文、きらきら・グラデーション

**やること**
1. 一番上に「誰から誰へ」と「次の一言」。文は1つだけ、それも原文の声かけ
2. 状態は形+記号+短い言葉。文は補足13pxに落とす
3. 済んだものは畳む(説明済み・履歴・記録の済んだ段)
4. 朱は止まれだけ。藍は構造だけ
5. 業務の言葉(「先に確認」「何まで」「話す順」)を見出しに使う。「サマリー」「ステータス」は使わない

## 5. 合格条件

自分たちで測れるもの(実装係が出荷前に確かめる):
1. お客様カード: 390×844 で開いた最初の画面に「先に確認(あれば)」「次の一言」「話す順の3行目」まで入る。スクロール0回
2. お客様カード: 店主(現場14年)以外の人に3秒見せて、「次に話すこと」と「先に誰に確認するか」を言える(家族など3人で3人)
3. お客様カード: 同じ情報が2か所以上に出ない(変更あり・前々回の約束・次の一言で数える)
4. 記録画面: 見本どおりの通常の記録が **タップ7回以内・文字入力0回**。どの段を開いても縦の長さが1.5画面以内
5. 記録画面: 店主が見本のお客様を3回記録し、3回とも30秒以内
6. 4状態: グレースケール表示と2型色覚シミュレーション(Chrome DevToolsの「視覚障害をエミュレート」)で、4つを言葉と形で区別できる
7. 320 / 375 / 390px幅で横スクロール0、文字切れ0、下のタブに隠れる要素0
8. タップ領域はすべて44×44以上、本文の文字は背景と4.5:1以上
9. 「見本データ」の注記と「目標30秒」の表示が、カード・記録・今日の3画面で残っている
10. `handoff.test.ts` を含む単体・統合テストが今と同じ件数で通る(ロジックに触れていない証拠)

現場で測れれば足すもの(Codex案): イベントスタッフ5人の5秒テスト、記録時間の中央値30秒・上位90%で40秒。

助言の全文は作業ログ(secretary/作業ログ/2026-10-07_UIデザイン部_売り場バトンUI方針.md)に保存。

**採った**
